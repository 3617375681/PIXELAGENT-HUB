# Software Studio（开发中）

当前已经能从控制台提交需求，由 Manager 规划、Coder 生成实际文件，再由 esbuild 构建自包含的静态浏览器应用。编译失败最多返修三轮，所有尝试保留；成功提供隔离预览、源码查看和源码 ZIP。支持追加需求、关联版本历史、内容对比和切回旧版；Tester 可生成有限的交互计划，独立浏览器可执行真实操作并保存截图和失败证据，完整需求覆盖与视觉验收仍需完善。

试玩页面会记录 JavaScript 运行异常与未处理 Promise 拒绝，可在“验证记录”查看，并点击“保存本次诊断”持久化到项目。实时记录刷新后清空，已保存记录保留版本、服务端保存时间和浏览器客户端来源；“页面已加载”或“未捕获异常”均不等于功能验收通过。监测脚本只用于控制台预览，不修改下载源码或构建报告。

诊断 API 为 `GET/POST /api/studio/projects/<UUID>/diagnostics`，写入 `diagnostics/<reportUUID>.json`。POST 必须提供当前 `previewFile`、布尔值 `loaded` 和最多 20 条 `errors`（每条 1–2000 字符）；旧预览或非成功项目返回 409。客户端观察不能作为可信 QA 或批准结果。

保存含异常的诊断后，点击“依据此诊断返修”。`POST /api/studio/projects/<UUID>/repair` 接收 `diagnosticId`，从服务器读取匹配的原源码与错误；Manager 重新规划，Coder 根据源码和诊断修正，Builder 再次真实编译。返修受创建限流、取消和超时控制，不自动重跑整个付费任务。

返修生成独立关联项目，`project.json.repair` 保存原项目 ID、诊断 ID、预览版本和错误，页面可返回原项目。原项目、源码和包不被覆盖，返修失败也能保留原成果。新构建仍为 `ready_for_review`，需要再次试玩；关联版本可在统一历史中查看和选用；构建不代表自动交互验收或已修复保证。

独立浏览器报告中的完整应用失败也可返修：展开报告后点击“依据浏览器失败返修（调用模型）”。服务端校验当前预览、计划和内容哈希，读取原源码与观察到的失败；新版本记录 `browserRunId`、`testPlanId` 和原项目关联。启动失败、超时、取消及过期报告不触发源码返修。完成后须为新版本生成计划并复测，详见 [浏览器返修流程](browser-verification.md#repair-from-browser-failures)。

成功返修或修改后打开“版本差异”，查看新增、删除或修改的文件及前后完整源码。`GET /api/studio/projects/<UUID>/changes` 从关联的构建源码快照计算内容差异，显示未变文件数量；没有变化时明确提示复测。普通项目、未完成或失败的派生版本返回 409。此处提供文件内容对比，暂不提供逐行高亮。

真实模型返修已有受控计数器实验：浏览器失败触发独立版本，复测原四项及额外七项检查。Manager 在返修时收到原源码，和 Coder 共用保留无关文件的说明；这次复测只改动错误数字，仍需查看每次实际差异并重新验收。证据与单样本限制见 [返修记录](benchmark-results/2026-10-09-real-repair-source-context/README.md)。

## 生成耗时与用量

作品详情的 `generationMetrics` 与基准报告共用统计逻辑，显示生成耗时、已返回角色任务、已报告 Token、缺失用量、模型及构建尝试/失败次数。页面同步展示这些信息；角色任务不等于实际模型 HTTP 请求数。

范围仅限当前版本 Manager/Coder 返回的任务结果，不包含 Tester、外部工具、父版本或没有返回结果的调用。无 usage 的失败请求明确标为缺失；Token 为已报告部分，不能当作完整账单。金额尚未计算，API 的 `costUsd` 保留 null。没有结束时间、无效时间或重启中断时，耗时为 null；生成中显示等待完成，不编造精确时间。

2026-10-08 通过原始基准记录的隔离副本验证：问答作品为 109.0 秒、12,864 Token、两项返回任务和一次构建；失败转换器为 18.0 秒、用量未报告、一项缺失任务，没有构建。此验证没有重新调用模型，也不修改原始项目。回归测试覆盖部分 usage、失败构建、API 字段及未知耗时。

## Tester 沙箱交互检查

成功项目可点击“生成交互检查（调用模型）”。Tester 依据原需求、累计修改说明和当前实际源码输出声明式 JSON：最多十项检查，每项最多八个点击、输入或合成键盘操作，最后比较指定元素的完整去空白文本或原生禁用状态。检查名称必须唯一，计划不能携带 JavaScript。模型同时列出覆盖限制；此角色仅在工作室检查模式注册。

`GET/POST /api/studio/projects/<UUID>/test-plans` 读取或创建计划；创建传空对象，取消传 `{ "cancelPlanId": "<计划UUID>" }`。计划写入 `test-plans/<UUID>.json`，通过原有后台运行队列、鉴权和创建限流执行，不自动重试付费任务；失败、取消及孤立任务保留明确状态。

点击“从初始页面运行检查”会重新加载隔离预览，按计划顺序共享页面状态。选择器必须恰好命中一个元素；文本不符或当前检查期间捕获运行异常均判失败，即使文本已符合预期。整个执行超过二十秒时显示失败。输入与键盘事件是合成事件，不能证明原生键盘激活、焦点导航、Canvas、像素视觉或异步计时行为正确。

保存结果复用诊断 API，附带 `testPlanId` 和 `checks`。服务器核对当前预览、计划、检查数量及名称；声明通过的实际文本必须等于计划预期，且不能附带错误。失败原因加入诊断错误，可用于现有返修流程。观察仍来自生成页面所在的浏览器客户端，不能作为独立可信证据；即使全部通过，也不更新 `browserVerified`、不批准交付。计划本身也需审阅是否覆盖需求。

## 人工验收

“人工验收”要求选择当前版本已保存的诊断、填写审阅者名称和说明，并明确勾选已实际试玩及审阅需求。可以记录“人工通过”或“需返修”。通过必须关联最新、已加载且无错误或失败检查的诊断；旧的干净记录不能掩盖更新的故障。检查全通过、切换候选版本和下载源码都不会自动批准。

`GET/POST /api/studio/projects/<UUID>/reviews` 读取历史或追加决定。POST 字段为 `previewFile`、`diagnosticId`、`decision`（`approved` / `changes_requested`）、`operator`（1–80 字符）、`note`（1–2000 字符）及 `manuallyReviewed: true`。决定写入独立的 `reviews/<UUID>.json`，保留服务端时间、关联诊断和 `manual-review` 来源；API 使用现有鉴权。审阅者名称是填写标签，不是已认证账号身份。

页面、项目列表和版本历史显示当前人工决定；生成状态仍为 `ready_for_review`，构建报告的 `browserVerified` 保持原值。追加需求和返修版本不继承批准；保存任何新诊断会使旧批准回到待验收，历史决定保留。下载仍用于审阅源码，不是发布操作。此功能记录操作者声明，不证明真人实际完成试玩，也不替代完整浏览器 QA。设计取舍见 [ADR](adr-001-manual-review.md)。

## 需求迭代与版本选择

成功版本可展开“在此版本上追加需求”，输入修改说明。`POST /api/studio/projects/<UUID>/revise` 接收 `changeRequest`（1–4000 字符），把基础源码和沿继承链保存的历次修改需求传给 Manager/Coder。原需求保留，修改需求同时写入新版本的 `requirements.md`；生成结果仍需构建和试玩。

“版本历史”按创建时间显示同一初始作品派生的返修与修改，支持从任意成功版本创建分支。每个版本使用独立 UUID 和生成目录，内部 `v1`–`v3` 是编译返修尝试，不是历史版本编号。

`GET /api/studio/projects/<UUID>/versions` 返回共同根项目、候选版本和历史。点击“使用此版本”（POST 同一路径，传 `projectId`）保存选择并打开该版本；可以切回旧版，其他成果保持可查看。选择写入根项目的 `version-selection.json`，刷新后保留。新生成不会自动替换候选版本，失败、取消、运行中或其他项目的版本不能选用。选择表示使用偏好，仍不等于人工验收或已交付。

## 创建与试玩

完整工作台可在应用目录执行 `npm run build:all`、`npm start`，使用同一个本机服务打开页面和 API。首次安装、端口及同源配置见 [本地启动](local-start.md)；热更新开发仍使用 API 与 Vite 两个终端。

容器部署使用仓库根目录的 Compose；运行时连接、持久化与容器检查范围见 [Docker 本机部署](docker-start.md)。

其他 Agent 或脚本可通过 [API 集成说明与 OpenAPI 契约](api-integration.md) 创建项目、读取证据并管理版本；调用模型的操作须显式触发。

启动 Records API 和 dashboard 后，打开 `/studio`（首页 STUDIO 按钮）。输入需求后点击“开始创作”，页面自动显示执行阶段，完成后可试玩、看源码与构建记录、下载 ZIP；刷新后根据 URL 恢复项目。取消不会开始后续代码生成。此流程受原有 API 鉴权、创建限流与运行队列控制。

API 项目保存在 `<RECORDS_ROOT>/studio/`；可用 `STUDIO_ROOT_OVERRIDE` 指定目录。CLI 默认使用 `records/software-studio/`。若要在页面加载 CLI 项目，可显式配置 API 指向该目录；不要让两个进程同时修改同一个项目。

软件生成默认总上限八分钟，可设置 `RUN_TIMEOUT_MS_STUDIO`。模式不自动重试整个付费生成任务；只在真实编译失败时进行最多三轮源码返修。

API 重启会把未完成任务明确记为中断失败，保留已有结果，不自动重复模型调用。任务历史使用串行原子保存，损坏文件不会被空历史覆盖；恢复步骤和验证边界见 [重启说明](recovery.md)。

失败或取消后，可点击“重新生成新版本（调用模型）”。新版本沿用原需求与修改/返修上下文，原错误和执行记录保留；模型产生新的用量。候选版本需手动选择并重新验收。重试流程的受控浏览器验证见 [手动重试记录](manual-retry-verification.md)。

在 `pixelagent-hub/` 安装依赖并配置本地 `.env` 的模型 provider：

首次安装可运行 `npm run studio:doctor` 检查模型配置与本地工具；`-- --browser` 额外验证带沙箱的 Chromium 启动。诊断范围及修复方式见 [环境检查](environment-check.md)。

```powershell
npm ci
npm run studio:create -- "制作像素贪吃蛇，包含方向键移动、暂停、计分和重新开始"
npm run studio:preview -- <上一步输出的项目UUID>
```

浏览器打开 `http://127.0.0.1:4175/`。预览只监听本机，可用 `STUDIO_PREVIEW_PORT` 改端口。Ctrl+C 停止预览；生成期间 Ctrl+C 取消模型请求。创建命令总上限八分钟。

产物位于 `records/software-studio/<UUID>/`：

- `project.json`：规划、模型信息、各轮代码和真实构建结果。
- `requirements.md`、`design.md`：需求及生成的计划。
- `v1/source/` 等：保留每次构建的原始源码。
- `v1/build-report.json` 等：真实编译错误或成功结果。
- 成功版本的 `dist/index.html`：无需安装的自包含页面。
- `source.zip`：源码、预览、构建报告和运行说明。

生成失败、超时或取消时返回失败状态，不输出可交付包。构建成功标为 `ready_for_review`，不自动标为验收通过。支持 HTML/CSS/JS/Markdown 文件，暂不支持 imports、npm 依赖、外部素材和服务端。工具不执行模型生成的 shell 或安装脚本。

## 成熟度验收清单

服务端独立浏览器检查已接入工作台，按保存的 Tester 计划执行真实操作并保存截图、错误和内容哈希。启用方式及覆盖边界见 [独立浏览器验证](browser-verification.md)；仍需完善任务覆盖与视觉验收后再勾选整体验收项。

固定案例运行器、单 Agent 对照方式和真实失败记录见 [基准说明](benchmark.md)。检查执行期间工作区标签暂时禁用，避免卸载正在执行的试玩页面；完成后恢复。

干净克隆的安装、入口修复及验证边界见 [安装验证](clean-install.md)。

- [x] 真实模型生成文件、真实编译、构建失败返修、源码 ZIP。
- [x] 独立本地预览；路径与资源限制；模型取消、失败记录。
- [x] 控制台创建项目、显示阶段、加载源码、试玩、下载。
- [x] Tester 根据源码生成声明式计划；执行沙箱 DOM 检查，保存结果及失败证据。
- [ ] 测试员依据需求实际操作浏览器，记录截图、运行错误和交互检查。
- [x] 按已保存的失败证据返修；独立人工决定，未确认时保持等待验收。
- [x] 同一作品追加需求，保留关联版本、源码对比、切回旧版及每版诊断记录。
- [ ] 重启后恢复项目和任务；取消、超时、断网不留下假成功。
- [ ] 至少五个固定应用案例与单 Agent 对照，公布成功率、耗时、成本和返修结果。
- [ ] 从干净克隆完成安装、运行和导出；CI、配置说明及发布文档齐全。

这些条目完成前，项目仍是原型。浏览器验收记录与构建报告分开保存，不把“模型说通过”当作工具测试。
