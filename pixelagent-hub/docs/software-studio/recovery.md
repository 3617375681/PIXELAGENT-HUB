# 本地任务持久化与重启

Records API 启动时读取 `<RECORDS_ROOT>/runtime-jobs.json`，将遗留的 `queued` / `running` 任务标记为 `failed`，错误为 `Recovered after process restart`。成功、失败和取消的历史保持原状；不会自动重复付费模型请求。恢复时的 `finishedAt` 表示服务器确认中断的时间，不能用于推断进程实际停止时间。

Studio 项目读取时与恢复后的任务状态同步。已成功构建的项目仍从原目录加载源码、预览、诊断、版本和人工决定。重新生成需要创建新任务；当前不支持从中断的模型调用或执行阶段继续。

任务历史通过临时文件和原子替换保存，同一进程中对同一路径的写入串行执行，保存入队时固定快照。不要让多个 API 进程共享同一记录目录；该机制不提供跨进程锁或事务，也不替代备份。

只有文件不存在时才初始化空历史。无效 JSON、错误的顶层结构、重复任务 ID 或无效状态/时间会导致初始化失败，原文件保留。遇到此类错误时：

1. 停止使用该记录目录的 API，备份整个目录。
2. 检查 `runtime-jobs.json`，优先从已知完整备份恢复；不要直接删除项目或覆盖历史。
3. 若选择新建记录目录，用 `RECORDS_ROOT_OVERRIDE` 指向新位置，保留旧目录供检查。

自动测试覆盖排队/运行状态恢复、终态和成功结果保留、24 个并发任务持久化、损坏文件保留，以及独立工作进程开始执行后被强制终止再恢复。运行：

```powershell
npx tsx --test src/web/runRuntime.test.ts
```

这些检查证明当前本地运行器的持久化与中断识别行为；完整服务进程的故障注入、跨平台断电、磁盘满和自动继续执行仍需单独验证。
