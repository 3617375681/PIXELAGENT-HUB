# 手动重试验证

2026-10-08，在独立本地 Records API 3124 和 dashboard 4344 验证失败后的恢复流程。模型端点是本地受控响应夹具，首次 Coder 请求故意返回 HTTP 503；此记录不作为真实模型生成质量或付费调用证据。

1. 创建“本地重试验证夹具（非真实模型）：计数器”。项目 `cf88bd5c-a1f8-4511-8539-a25147722d80` 保存失败，界面显示 Manager 完成、Coder 失败、Builder 未执行，原始 HTTP 503 错误可见。
2. 点击“重新生成新版本（调用模型）”，创建项目 `3b04303f-69c3-4e8f-a5ff-220d01e739c8`。需求不变，`retry.parentProjectId` 指向原失败项目；真实编译成功，仍为 `ready_for_review`，没有人工通过记录。
3. 版本历史包含失败的 V1 和重新生成的 V2。原失败作品不能选择，新作品未自动成为候选版本。点击“使用此版本”后刷新，V2 恢复“当前使用”。
4. 试玩夹具计数器，点击“增加”后文本从 0 变为 1。回到原项目后原错误和重试入口仍可查看；磁盘保留两个项目和独立版本选择文件。

后端回归覆盖失败/取消重试、旧记录不变、正在停止的任务拒绝重试、独立验收状态、重复重试不重复追加需求、返修源码与诊断继承、认证和限流。服务重启回归保留中断阶段，且不自动重复调用模型。前端测试覆盖失败、取消、中断、编译返修和缺少阶段证据的旧记录。

本轮验证：框架构建、包入口冒烟检查、130 项后端测试、Dashboard 类型检查和 22 项测试通过。

重试从头执行；没有继续中断的模型请求或执行阶段。完整浏览器自动验收、真实网络故障恢复和重复基准运行仍需进一步验证。
